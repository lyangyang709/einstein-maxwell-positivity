# Contributing

## Before starting

1. Open an issue or leave a short YourScience workspace note identifying the
   claim, equation, or transformation you plan to check.
2. State the source version, metric and curvature conventions, EFT truncation,
   and whether the task is analytic, symbolic, or numerical.
3. Do not run code copied from papers, posts, or third-party repositories
   without inspecting it and isolating the environment.

## Pull requests

- Keep one check or logically connected derivation per pull request.
- Include exact reproduction commands and dependency versions.
- State what was actually run and what remains planned.
- Add a regression or limiting-case check where possible.
- Do not rewrite another contributor's results without preserving attribution
  and revision history.

## Result labels

Use one of these labels in research notes and tables:

- `verified`: independently checked against the pinned source or calculation;
- `quoted`: transcribed from a pinned source but not independently derived;
- `inferred`: reconstructed from context and awaiting confirmation;
- `unresolved`: evidence or conventions are insufficient;
- `contradicted`: a reproducible check disagrees with the stated claim.

## Security and privacy

Never commit API keys, tokens, cookies, private operator instructions, local
paths containing personal data, or unpublished third-party materials.
